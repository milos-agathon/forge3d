## Qualified algorithm

The model uses the runtime's 10×10×64 froxel grid, including its border, and
the existing 192-direction Fibonacci quadrature. It keeps 622 occupied
froxels in **both** ablation arms, including medium below the open terrain.
Each direction has its own continued source. Gathering uses HG weights
with the authored `g = 0.45`; it never assumes angularly constant radiance.
Continuation takes the existing 64 depth steps. Density optical depths use
the exact trilinear two-node Gauss integral; visibility uses bilinear roots.

The surface term is regenerated by the same preserved program. A diffuse
cache at the froxel grid's 10×10 horizontal positions couples surface return and medium
continuation. Its environment irradiance is attenuated by the medium and
blocked only at actual surface crossings. It also receives the medium's
in-scatter return. Final surface irradiance is evaluated at the actual
primary intersections using the same 192 directions. The existing primary
direct-sun term stays owned by terrain shading; the new texture stores a
signed correction to environment irradiance plus the complete medium return.
Every new lighting visibility query uses the terrain-occlusion flag.

The cache samples the full authoritative DEM bilinearly. Increasing DEM
resolution alone changes neither its dimensions nor allocation. Starting
from zero, CPU source iteration reaches an identical stored-f16 source/cache
at order **19 in both arms**. Production no longer has a fixed 21-order loop.
GPU atomics compare both stored fields after every update; the host stops
only when neither changes. Overflow or loss of monotonicity raises an error.
No chosen order cap is used. A u32 counter overflow is a representation error.
This proves a fixed point of the stored operator, not convergence of the
continuous reference integral.

The solver reads a tracked **16-byte** progress buffer per order on a cache
miss. Completely identified static environments reuse converged fields when
all uniforms/provider keys match. Live rendered skies conservatively solve
again. Viewer diagnostics take only the adapter and read CPU metadata:
**no per-frame diagnostic readback**. They explicitly mark an incomplete
query count when only a lower bound is known. Explicit acceptance captures
may still read actual primary-hit evidence. Transport rebuilds can stall;
real-DEM frame timing remains a release blocker.

GPU storage packs only occupied froxels into two f16 source textures and
one texture containing exact f32 incoming-radiance bits. The latter uses
integer texture storage and bitcasts, so it needs no float-filtering feature.
An uploaded froxel-to-active-index texture preserves zero sources outside
the occupied set. This removes the dense whole-view storage-buffer binding
limit without changing transport weights. The first surface-order cache is
retained for the single/multiple diagnostic split. Resource sizes and host
staging are tracked, including the progress and readback buffers. Physical
Gate 6 memory evidence remains pending.

The earlier `coupled-surface.npz` is used only for comparison. It has no
preserved generator and is not an input to the new transport. On shadowed
terrain the new boundary differs by roughly (+0.001379, +0.001747, +0.002117)
mean linear RGB, with mean absolute differences about (0.005915, 0.005083,
0.004310). The largest channel difference is about 0.480. The full comparison
is in the JSON; the old cache's internal choices cannot be reconstructed.
